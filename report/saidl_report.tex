\section{CORE ML TASK}

\subsection{Introduction \& Experimental Setup}
I designed a modular sequence model using PyTorch. Going into this, my main resources were the Stanford CS231n lectures for understanding the neural network fundamentals, and various PyTorch tutorials for the actual implementation. My goal was to build a backbone where I could easily swap out different attention layers and positional encodings to see how they affected memory and perplexity. 

Everything was trained on my local setup: an NVIDIA RTX 4050 with just 6GB of VRAM. This strict memory limit actually forced me to really understand what was going on under the hood, because any inefficient code would instantly result in an Out-Of-Memory (OOM) error. I used the WikiText-2 dataset, a sequence length of 512, and a batch size of 16.

\subsection{Theoretical Analysis of Positional Encodings}

\subsubsection{Sinusoidal Positional Encoding (Baseline)}
Without positional encodings, a Transformer treats a sentence like a bag of words. The standard approach adds sine and cosine waves to the embeddings. However, I found that this hardcodes an absolute position to each word. When I tried to evaluate the model on sequences longer than what it was trained on, it completely broke down because it had never seen those absolute coordinates before.

\subsubsection{Rotary Positional Embedding (RoPE)}
I wanted something that cared about \emph{relative} distance, not absolute position. I came across RoPE, which sounded complicated but made sense after watching some 3Blue1Brown (3b1b) videos on complex math and rotations. Instead of adding numbers to the embeddings, RoPE rotates the Query and Key vectors in 2D space based on their position. Because of how dot products work with angles, the attention score between two words ends up depending only on how far apart they are from each other, completely ignoring their absolute position in the sentence.

\subsubsection{ALiBi and Relative PE}
ALiBi was the simplest to implement. Instead of messing with the embeddings, I just subtracted a linear penalty directly from the attention scores based on how far apart the words were. I also tried Shaw's Relative Positional Encoding, which explicitly learns a vector for the distance between tokens. Both of these approaches worked infinitely better than the baseline for long contexts.

\subsection{Exploring Attention Variants}

To stop my GPU from running out of memory, I looked into optimizing the standard attention mechanism.

\subsubsection{Multi-Query Attention (MQA)}
While reading through PyTorch implementation guides, I learned that during text generation, the bottleneck isn't usually the math itself, but the memory bandwidth required to move the Key and Value matrices around. MQA fixes this by sharing a single Key and Value projection across all the different Query heads. Implementing this instantly dropped my memory usage and sped up generation significantly.

\subsubsection{Sliding Window Attention}
I realized that for most text, a word really only cares about the words immediately surrounding it, not something 500 words away. Sliding Window attention just restricts the model to look at a fixed window of previous tokens, bypassing a lot of unnecessary calculations.

\begin{lstlisting}[language=Python, caption=Exact causal masking in Sliding Window Attention.]
# Causal mask logic implemented in core_ml/attention.py
causal = torch.tril(torch.ones(T, T, dtype=torch.bool, device=x.device))
window = torch.triu(torch.ones(T, T, dtype=torch.bool, device=x.device), diagonal=-(self.window_size - 1))
sw_mask = causal & window
\end{lstlisting}

\subsubsection{Linear Attention}
I wanted to see if I could make attention scale linearly instead of quadratically. By using a math trick with matrix associativity, you can multiply the Keys and Values together \emph{before} multiplying by the Queries. This requires replacing the standard Softmax with a different function (I used \texttt{elu(x) + 1} so everything stays positive), but it allowed me to run much longer sequences without OOM errors.

\subsection{Mixing Convolutions and Attention}

From watching the Stanford CS231n lectures, I knew Convolutions are amazing at finding local patterns (like edges in images, or n-grams in text). Transformers, on the other hand, are great at global context. I decided to try combining them to get the best of both worlds.

\subsubsection{Design 1: Conv1D Before Attention}
I wrote a custom block that inserted a 1D Convolution right before the attention layer. By padding the input correctly, it acts as a causal filter, effectively giving the model a 7-gram local context window for free before it even starts doing the heavy global attention math.

\subsubsection{Design 2: Gated Depthwise Conv FFN}
Inspired by some more advanced PyTorch implementations, I tried completely replacing the standard FeedForward network with a Gated Convolutional FFN. By using a depthwise-separable convolution, it provided local positional context without the massive computational cost of a standard convolution.

\section{DOMAIN TASK RACD}

For the domain task, I moved from text to images. Using PyTorch tutorials, I set up a basic Diffusion Transformer (DiT) operating on latent spaces via a pre-trained VAE.

\subsection{The Idea behind RACD}
Standard diffusion models spend the same amount of time denoising a complex face as they do denoising a blank blue sky. I implemented "Global Cyclic Refinement," which essentially does a second pass over the image to polish it up by adding noise back in and denoising again. The problem is that doing this for the whole image is incredibly slow.

My thought process was: what if we only refine the hard parts? I built a small CNN "Difficulty Predictor" that looks at the intermediate features of the diffusion process. It outputs a mask that tells the model which patches of the image are struggling. We then use a threshold $\tau$; if a patch is harder than $\tau$, we refine it. If not, we skip it.

\begin{lstlisting}[language=Python, caption=RACD dynamic difficulty masking.]
# Re-injection masking logic implemented in diffusion/racd.py
difficulty_mask = torch.sigmoid(predictor(h)) # h is DiT features
mask_bool = difficulty_mask > tau
x_t = torch.where(mask_bool, x_noisy, x_clean)
\end{lstlisting}

\subsection{Analysis of RACD Hardware Overhead}
While RACD theoretically reduces the number of denoising FLOPs by selectively targeting patches, our empirical results show a \textbf{659.7\% increase} in wall-clock compute time (11.744s vs 1.546s per image). This is a classic example of \textbf{CUDA synchronization overhead}. 

Evaluating the conditional mask $M_{ij} > \tau$ and dynamically selecting spatial indices forces the GPU to constantly synchronize with the CPU to determine control flow during every timestep of the diffusion loop. In a naive PyTorch implementation without fused custom CUDA kernels (e.g., Triton or CUDA C++), this GPU-CPU blocking completely destroys tensor parallelism. Thus, while mathematically elegant, dynamic spatial sparsity requires specialized low-level hardware optimizations to yield actual wall-clock speedups.
